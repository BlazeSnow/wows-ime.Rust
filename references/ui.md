# 界面与交互

前端为 React + TypeScript，组件库 shadcn/ui（Tailwind CSS v4），暗色模式跟随系统。

## 布局

```
┌──────────────────────────────────────────────┐
│ 标题栏：应用名 + 一句话说明                       │
├────────┬─────────────────────────────────────┤
│ 导航    │ 内容区（滚动）                          │
│ 主页    │                                      │
│ 设置    │                                      │
└────────┴─────────────────────────────────────┘
```

- 左侧固定宽 40 栏导航，当前项高亮。
- 右侧内容区独立滚动，窗口缩放时导航不折叠（最小窗口 860×600）。
- 右下角挂 `Toaster`，所有操作反馈以 toast 呈现（成功/警告/错误/信息）。

## 主页

三步向导由 `step` 状态驱动，顶部一行显示进度（「第 N 步，共 3 步」）与上一步/下一步/写入配置按钮；内容区按步骤切换。

- 步骤切换由状态驱动，不使用路由，便于与原版 WinUI 的 `NavigationView` 行为对齐。
- 第 1 步路径列表用原生 `radio`，保证键盘可达与唯一选中语义。
- 第 2 步输入法列表为「名称 / 分类 / 操作」三列网格，勾选用 `Checkbox`，分类用 `Select`，自定义项额外给删除按钮；系统扫描到的项用 `IME` 徽标区分来源。
- 第 3 步只做汇总展示，不允许在此修改选择。

## 设置页

- 界面语言：下拉选择，**立即生效**（i18next 运行时切换），并持久化到设置库。
- 软件版本：展示后端返回的 `CARGO_PKG_VERSION`。
- 项目官网 / 项目仓库：按钮调用系统默认程序打开链接，失败时给出错误提示。

## 对话框

三类确认框都用 `AlertDialog`：

1. 删除自定义游戏路径
2. 删除自定义输入法
3. 写入前确认（覆盖 / 新增）

「添加自定义输入法」用 `Dialog`（带输入框与分类下拉），取消与确定都显式给出。

## 约定

- 用户可见文案一律走 `t()`，不在组件里写死中文；新增文案必须同步补齐 `zh-Hans` / `zh-Hant` / `ja` 三份资源。
- 状态提示统一用 toast，不在页面里维护第二套提示条。
- 后端错误以 `{ code, detail? }` 形式返回，前端把 `code` 映射为可读文案；后端不返回堆栈。
